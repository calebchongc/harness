# Harness v0.2.123

## Interactive native visuals in desktop conversations

An answer can now include something you can use: a small interactive scenario,
comparison, chart, or calculator inside the conversation. Ask Graff to compare
capacity plans, for example, and it can publish a native visual with labeled
charts, statistics, sliders, toggles, and buttons. Changing a control updates
the visual locally; it does not make another model request.

The new Harness MCP tool, `show_visual`, accepts a title and a bounded Luau
script. Harness renders its output using the app's own theme and native
controls rather than an embedded website. Scripts cannot access files, the
network, shell commands, or application APIs. Setup and interactions run off
the UI thread with memory, execution-time, and output limits.

The title and source are saved with the conversation and synchronize between
devices. Control state is temporary and local: reopening the conversation,
restarting the app, or evicting a visual from the bounded resident cache resets
it to its initial state. This first version supports two-dimensional native
components, not arbitrary HTML, custom styling, 3D, or persistent shared apps.

Mobile rendering is not included. Updated mobile decoders show the visual's
title with a notice to open it in Harness desktop; older mobile apps skip the
visual and retain the rest of the conversation. Desktop UI and engine versions
should be updated together, as they are in the packaged app.

See [Native visuals](https://github.com/justrach/harness/blob/v0.2.123/docs/native-visuals.md) for authoring examples, sandbox limits,
and an isolated development demo. Illustrative estimates should always be
labeled as synthetic; visuals do not make their underlying data authoritative.
