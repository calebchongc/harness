# Harness v0.2.136

Desktop release for macOS, Windows and Linux: long chats stay responsive
while an agent streams, Harness logs what it was doing if it ever stalls, and
"tell me when it's done" alerts follow who actually asked for the work. On
iOS, the chat header steps between sessions in place, the Home controls read
as one row, and the remote folder browser opens folders instantly.

This is the first release that installations on v0.2.135 pick up with the
new titlebar update icon: they download it in the background and restart
into it on their own once nothing would be interrupted.

## Chats

- A long conversation no longer slows down as an agent streams into it. Each
  new token used to redo work for the whole transcript on the main thread
  (the message rail's prompt previews and every tool group's animation); on a
  3,200-turn chat that took about 78 ms per token in a debug build, and now
  about 10 ms. Opening that chat went from 73 ms to 21 ms (#342).
- If the app ever stops responding for more than 5 seconds, Harness logs what
  the main thread was busy with (the action, input event or task, and the
  window's route and transcript size) and how long it lasted. On macOS a stall
  of 10 seconds or more also saves one stack sample to the logs folder (at
  most once every 30 minutes, newest three kept). The logs carry no chat
  content. This is so the next minutes-long freeze can be diagnosed (#342).

## Agents

- Completion alerts follow who asked for the work. A turn the agent continues
  on its own keeps the last prompt's owner, so "tell me when it's done" still
  chimes; work another agent asked for stays silent. A chat whose row arrives
  after its session still gets its alert, and an archived chat never alerts
  (#499).
- Messages from another agent can't wake an archived chat, even when they're
  marked only by where they came from rather than by their text (#498).

## iOS

- The session header steps between sessions with arrows in place of the
  floating session pill, and status indicators no longer act as buttons. In a
  stacked split, Split and ✕ stay on the bar (#430).
- Home's project and grouping controls sit together above the list as two
  matching pills: **All projects** (or the project's name) and **By time / By
  project / By device**. The bar only shows the connection status, when there
  is one, and VoiceOver reads the current project (#419).
- The remote folder browser shows folders you've visited instantly and
  refreshes them in the background; going back no longer waits on the
  computer, and taps stay responsive while a folder loads. Pull to refresh,
  and a failed folder says why. The computer lists folders faster, checking
  for git only in the folders it returns, several at once (#420).

Mobile builds are distributed separately; this desktop release does not itself
update TestFlight, App Store or Play installations.
